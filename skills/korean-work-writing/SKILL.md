# 한국어 업무 글쓰기

독자가 내용을 이해하고 다음 행동을 판단할 수 있게 쓴다. 자연스러운 표준 한국어, 짧고 구체적인 설명, 일관된 종결을 기본으로 삼는다. 발표·문서의 대상과 목적에 맞게 표현의 밀도를 조정한다.

## 적용 범위와 우선순위

- 사용자가 지정한 어투·독자·형식과 작업 폴더의 지침을 우선한다. 별도 지정이 없으면 아래 기본 문체를 적용한다.
- 사용자와 나누는 반말 대화와 납품할 문서의 문체를 구분한다. 채팅 말투를 문서에 그대로 옮기지 않는다.
- 문체 교정은 의미를 보존하는 작업이다. 정책, 책임, 조건, 예외, 수치, 출처와 승인 상태를 바꾸지 않는다. 내용 변경이 필요하면 문체 수정과 구분해 알린다.
- 특정 프로젝트의 기술·승인 절차·문서 구조를 다른 업무의 필수 기준으로 가져오지 않는다.

## 기본 문체

| 위치 | 기본 방식 | 예시 |
| --- | --- | --- |
| 제목·소제목 | 핵심이 드러나는 짧은 명사구 또는 질문 | 공통 기준의 역할 / 같은 AI, 다른 결과 |
| 문서 본문 | 차분한 설명의 ‘합니다’체 | 작업을 시작하기 전에 기준 문서를 확인합니다. |
| 발표 화면 | 핵심 문구는 짧게, 완결된 설명은 ‘합니다’체 | 기준 확인 → 작업 → 검증 → 기록 |
| 발표 설명 | 소리 내어 읽기 자연스러운 ‘합니다’체 | 같은 답변을 받아도 확인하는 내용은 달라집니다. |
| 절차·확인 목록 | 행동과 대상을 명확히 쓰고 같은 문법으로 나열 | 기준 문서 확인 / 변경 범위 확인 / 검증 결과 기록 |

- 같은 설명에서 ‘합니다’, ‘해요’, ‘한다’를 오가지 않는다. 기존 문서가 일관된 다른 문체를 쓰거나 사용자가 요청하면 그 문체를 유지한다.
- 제목·표·목록의 짧은 명사구와 본문의 완결된 문장은 함께 쓸 수 있다. 모든 문구에 억지로 ‘합니다’를 붙이지 않는다.
- 발표 설명을 대화체로 쓸 때도 ‘그렇죠?’, ‘아시겠지만’, ‘여러분도’, 감탄사와 청중을 평가하는 표현을 습관적으로 넣지 않는다.

## 문장과 흐름

- 전달할 요점이나 해야 할 행동을 먼저 쓴다. 필요한 이유·조건·예시를 뒤에 연결한다.
- 한 문단은 한 주제를 다룬다. 긴 문장은 주체·행동·조건이 구분되는 곳에서 나눈다. 조건과 예외가 본문에서 떨어져 의미가 달라지지 않게 한다.
- 추상적인 명사보다 누가 무엇을 하는지 쓴다. ‘진행’, ‘수행’, ‘활용’, ‘체계’, ‘고도화’를 무조건 금지하지 않고, 구체적인 행동으로 바꿀 수 있을 때 바꾼다.
- ‘~에 대한 ~의 ~’, ‘~을 통한 ~’, ‘~하는 것이 가능합니다’가 겹치면 직접적인 동사로 고친다. 익숙한 한국어를 어색한 번역투로 바꾸지 않는다.
- 같은 근거를 도입·본문·마무리에서 반복하지 않는다. 앞에서 이유를 설명했다면 다음에는 방법·사례·판단 기준으로 나아간다.
- 대비, 비유, 질문형 제목은 이해에 도움이 될 때만 사용한다. ‘X가 아니라 Y입니다’나 ‘핵심은’ 같은 틀을 반복하지 않는다.
- 비유를 먼저 선언하고 설명을 끼워 맞추지 않는다. 실제 상황을 보여준 뒤 필요한 만큼 연결한다. 비유를 빼도 핵심 설명이 성립해야 한다.
- 문장을 짧게 만들려고 인과관계를 끊거나 단문을 지나치게 나열하지 않는다.

## 용어와 정보의 정확성

- 같은 개념은 같은 용어로 쓴다. 독자가 알아야 하는 약어·전문 용어는 처음 나올 때 짧게 설명한다. 입문 자료에서는 쉬운 설명을 먼저 둔다.
- 공식 명칭, 코드 식별자, 파일명과 명령은 보존한다. 영어를 모두 번역하거나 낯선 음사·조어를 만들지 않는다.
- 확정된 기준, 제안, 예시, 미확인 내용을 구분한다. ‘권장’을 ‘필수’로, ‘검토’를 ‘승인’으로, ‘문서 검토’를 ‘동작 검증 완료’로 바꾸지 않는다.
- 미확정 사항은 독자가 결정할 내용을 알 수 있게 적는다. 문맥상 명확한 상태 표시를 모든 문장에 반복하지 않는다.
- 출처 없는 성과·수치·효과를 덧붙이지 않는다. 구체적인 예시가 필요해도 실제 정책처럼 보이는 내용을 만들어 넣지 않는다.
- 의도하지 않은 한자·중국어 문자와 깨진 문자를 남기지 않는다. 실제 인용, 번역 대상, 고유명사와 코드 식별자는 보존한다.

## 매체에 맞게 정리하기

- **가이드·업무 문서:** 적용 조건, 해야 할 행동, 확인 기준을 필요한 순서로 쓴다. 백과사전식 배경이나 독자가 이미 아는 상식을 늘어놓지 않는다.
- **발표 자료:** 화면에는 핵심을, 발표 설명에는 연결과 예시를 둔다. 화면에 설명문 전체를 복제하지 않는다. 최종본에서 설명·검토 메모를 제외할지는 사용자가 정한 형식을 따른다.
- **브리핑·결과 보고:** 무엇이 달라졌는지, 왜 필요한지, 무엇을 확인했는지 중심으로 쓴다. 실행하지 않은 검증은 완료로 표현하지 않는다.
- 비교는 표, 순서는 번호 목록, 관계·흐름은 필요한 경우 다이어그램을 사용한다. 단순한 문장으로 충분하면 형식을 늘리지 않는다.

## 작업 방법과 마무리 확인

1. 대상과 인접 문맥을 읽고 독자·목적·기존 종결·주요 용어를 확인한다. 작은 교정에 전체 저장소를 읽지 않는다.
2. 기본 문체를 정하고 의미와 조건을 보존하며 수정한다. 제목·표·목록도 같은 개념과 문법을 쓰는지 함께 확인한다.
3. 발표 설명은 소리 내어 읽는 속도로 검토한다. 문서 본문은 독자가 무엇을 이해하거나 해야 하는지 바로 알 수 있는지 확인한다.
4. 원문과 비교해 사실·조건·상태가 바뀌지 않았는지, 어투가 섞이지 않았는지, 반복·번역투·억지 비유가 남았는지 확인한다.

표현을 판단하기 어렵거나 교정 예시가 필요할 때만 [표현 예시와 기준 출처](references/examples.md)를 읽는다. 이 스킬만으로 원본 문서의 편집이나 외부 문서 갱신을 수행하지 않는다. 요청받은 파일과 범위에 적용한다.
