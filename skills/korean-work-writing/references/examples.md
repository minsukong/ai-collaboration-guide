# 표현 예시와 기준 출처

## 예시를 읽는 기준

아래 문장은 문체 판단을 돕는 예시다. 모든 문서를 같은 문장으로 바꾸는 치환 규칙이 아니다. 원문에 있는 조건·상태·주체가 예시보다 구체적이면 그 내용을 유지한다.

| 다듬기 전 | 다듬은 예 | 판단 기준 |
| --- | --- | --- |
| AI 활용의 효과를 일회성 산출물에서 지속 가능한 업무 수행으로 확장합니다. | AI가 만든 결과를 다음 업무에서도 활용할 수 있어야 합니다. | 독자가 이해할 수 있는 행동으로 표현한다. |
| 검증 프로세스의 수행을 통해 결과물의 신뢰성을 확보합니다. | 담당자가 결과를 확인하고, 문제가 있으면 수정한 뒤 다시 검증합니다. | 추상적인 효과보다 실제 절차를 설명한다. 원문에 담당자와 절차의 근거가 있을 때 쓴다. |
| 문서 확인을 진행하는 것이 가능합니다. | 문서를 확인할 수 있습니다. | 의미 없는 명사화와 우회 표현을 줄인다. |
| 결과를 확인해요. 문제가 있으면 수정합니다. | 결과를 확인합니다. 문제가 있으면 수정합니다. | 한 설명 안의 종결을 통일한다. |
| AI는 거울입니다. 거울이 사람을 잘생기게 만들지는 않습니다. | 같은 AI를 써도 누구는 답을 그대로 받아들이고, 누구는 오류를 찾습니다. 대화에는 우리가 아는 것과 놓치는 것이 드러납니다. 그런 점에서 거울과 닮은 구석이 있습니다. | 실제 차이를 먼저 보여주고 비유를 가볍게 연결한다. |
| 누구나 쉽게 완벽한 결과를 만들 수 있습니다. | 이 자료는 기준 확인부터 결과 검토까지의 작업 순서를 안내합니다. | 근거 없는 효과 대신 자료가 실제로 제공하는 내용을 쓴다. |

## 짧게 써도 보존할 것

- 원문: ‘계약이 확정되고 담당자가 승인하면 적용을 검토합니다.’ → ‘바로 적용합니다’로 줄이지 않는다. 조건·승인·검토 상태가 모두 사라진다.
- 원문: ‘문서 구조와 링크를 확인했습니다. 실제 앱 테스트는 실행하지 않았습니다.’ → ‘검증을 완료했습니다’로 합치지 않는다.
- 원문: ‘공통 기준 사용을 권장합니다.’ → ‘공통 기준을 사용해야 합니다’로 강화하지 않는다.
- 제목·단계의 ‘기준 확인 → 작업 → 검증 → 기록’은 자연스러운 요약이다. 본문 전체를 ‘확인함·진행함·완료’로 축약하는 근거가 되지는 않는다.

## 기준을 추출한 자료

2026-10-30 다음 로컬 문서의 실제 지침과 표현을 확인했다. 아래 경로는 기준의 출처이며 스킬 실행의 필수 의존성은 아니다. 다른 프로젝트에서는 이 파일이 없어도 SKILL.md의 원칙을 적용할 수 있다.

- `lounge-docs/AGENTS.md`: 자연스러운 표준 한국어, 통용되는 명칭, 깨진 문자 방지.
- `lounge-docs/docs/AGENTS.md`: 판단 기준 중심의 짧은 설명, 문단당 한 주제, 반복 제거, 확정·미확정 구분, 단순한 내용에 표를 강요하지 않는 기준.
- `lounge-docs/docs/common-source/briefing.md`: 차분한 ‘합니다’체, 적용 조건과 실제 확인 범위의 구분.
- `lounge-docs/docs/common-source/test.md`: 행동·대상·조건을 연결하는 구체적인 설명.
- `lounge-docs/docs/workflow/usage-guide.md`: 목적에서 실제 사용 방법으로 이어지는 흐름, 필요한 용어·예시만 연결하는 방식.

발표 화면·발표 설명의 구분과 비유 사용 기준은 위 문서들의 편집 원칙을 발표 작업에 맞게 확장한 권장 방식이다. 원본 docs가 명시한 프로젝트 필수 규칙으로 해석하지 않는다.
